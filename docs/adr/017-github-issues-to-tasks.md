# ADR-017: GitHub → งาน: ดึง issue ที่มอบหมาย (milestone = วัน) · GitHub เป็นเจ้าของตาม "การเปลี่ยน" · webhook ต่อผู้ใช้ตรวจ HMAC จาก body ดิบ

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-10-17

## บริบท

สเปก 15: "GitHub integration (webhook ปิด task เมื่อ PR merged)" · เจ้าของเพิ่ม: ล็อกอินด้วย GitHub แล้ว**ดึงงานจาก GitHub ลงปฏิทิน**
ข้อเท็จจริง: issue ของ GitHub **ไม่มี due date** · ผู้ใช้แก้งานใน NOSION ได้ (เลื่อนวัน ติ๊กเสร็จ ลบ) · Vercel Function มีเวลา 10 วิ ·
entry มี `clientId` unique ต่อผู้ใช้ (Phase 7) · payload ของ task มีช่อง `github` ตั้งแต่สเปก

## การตัดสินใจ

1. **ดึงด้วย `GET /issues?filter=assigned`** (OAuth token ของผู้ใช้ · ADR-016) — ครั้งแรกเฉพาะที่เปิดอยู่ · ครั้งต่อไปทุกสถานะ `since` รอบก่อน − 1 ชม. ·
   ดึงรอบแรกทันทีหลังเชื่อม (event ระหว่างโมดูล ไม่ import ข้ามกัน) + cron รายชั่วโมง + ปุ่ม "ดึงตอนนี้"
2. **วันในปฏิทิน = `milestone.due_on`** · ไม่มี milestone = งานไม่มีกำหนด (ไม่เดาวัน)
3. **`clientId = gh:<node_id>`** — ดึงกับ webhook มาพร้อมกันก็ไม่สร้างซ้ำ (unique index เดิม) · สร้าง/แก้ผ่าน `EntriesService` ตัวเดียวกับแอป
4. **GitHub เป็นเจ้าของตาม "การเปลี่ยน" ไม่ใช่ทับทุกครั้ง** — จำ `state` และ `milestoneDueOn` ที่ซิงก์ครั้งก่อนใน payload:
   ปิด/เปิดงานเมื่อ state บน GitHub เปลี่ยน · เขียนวันทับเมื่อ milestone due เปลี่ยน · ผู้ใช้ลบงาน = ไม่สร้างใหม่ · issue ที่ปิดก่อนเคยดึง = ไม่สร้าง
   (ตัดสินใน pure function `planIssue` — เทสต์ได้ไม่ต้องมี DB/เครือข่าย)
5. **webhook ต่อผู้ใช้** `POST /webhooks/github/:id` · secret สุ่ม แสดงครั้งเดียว เก็บแบบเข้ารหัส · ตรวจ `X-Hub-Signature-256` จาก **body ดิบ** (`rawBody: true`) ·
   ลายเซ็นผิด/id มั่ว/ปิดแล้ว = 404 เหมือนกัน · event `issues` = อัปเดตทันที · `pull_request` merged = ปิดงานที่อ้าง `nosion:<id>` หรือที่ดึงมาจาก PR นั้น
6. "Closes #n" ไม่ parse เอง — GitHub ปิด issue แล้วส่ง `issues.closed` ตามมาเอง

## ทางเลือกที่ไม่เลือก

| ทางเลือก                                         | เหตุผลที่ไม่เลือก                                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| วันจาก GitHub Projects v2 (date field)           | ต้อง GraphQL + scope `read:project` · ผู้ใช้ส่วนใหญ่ไม่ได้ใช้ Projects                            |
| ใส่วันที่สร้าง issue / วันนี้ ให้ทุก issue       | ปฏิทินเต็มไปด้วยวันปลอม — ข้อมูลที่ผิดแย่กว่าข้อมูลที่ไม่มี                                       |
| GitHub ทับทุกช่องทุกครั้ง (source of truth เต็ม) | ผู้ใช้เลื่อนวัน/ติ๊กเสร็จใน NOSION แล้วถูกดึงกลับทุกชั่วโมง                                       |
| sync สองทาง (ปิดงานใน NOSION → ปิด issue)        | ต้องขอ `repo` (เขียน) จากทุกคน · ปิด issue ของทีมจากแอปส่วนตัวเป็นผลข้างเคียงที่ไม่ควรเกิดเงียบ ๆ |
| GitHub App (webhook ระดับ installation)          | ติดตั้งครั้งเดียวได้ทุก repo + สิทธิ์อ่านอย่างเดียว แต่ตั้งค่า/ติดตั้งยากกว่ามาก (ดู ADR-016)     |
| เก็บ `X-GitHub-Delivery` กันส่งซ้ำ               | ทุกการกระทำ idempotent อยู่แล้ว (upsert ด้วย clientId · ปิดงานที่ปิดแล้ว = ข้าม)                  |

## ผลที่ตามมา

**ได้:** งานจาก GitHub ขึ้นหน้า Today · ปฏิทิน · ⌘K · Weekly Review โดย core ไม่รู้จัก GitHub (เป็นแค่ entry ของโมดูลงาน) ·
ปลอดภัยต่อการยิงพร้อมกัน (unique index) · ทดสอบทั้งชุดได้โดยไม่ต่อ GitHub จริง

**เสีย:** issue ที่ไม่มี milestone ไม่ขึ้นปฏิทิน (อยู่ในงานไม่มีกำหนด) · webhook ต้องเปิดทีละ repo ·
ดึงได้สูงสุด 300 รายการต่อรอบ · โทเคนถูกเพิกถอนรู้ตอนดึงครั้งถัดไป (แสดง error ในการ์ด)
