# ADR-018: i18n — ภาษาในคุกกี้ + rewrite ภายใน (URL ไม่มี `/en`) · static ทั้งสองภาษา · ข้อความฝั่งเซิร์ฟเวอร์ตาม `settings.locale`

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-10-17

## บริบท

สเปก 8.9: `next-intl` ไทย (ค่าเริ่มต้น) + อังกฤษ · วันที่/เงินด้วย `Intl` · ปีพุทธศักราชเลือกได้ · ICU plural
ข้อเท็จจริง: ข้อความไทยฝังในโค้ด ~900 บรรทัด · ทุกหน้า prerender เป็น static (Lighthouse ≥ 90 ขึ้นกับ TTFB) · service worker แคชหน้าตาม path ·
API ประกอบข้อความเอง (การ์ด Today · สรุปสัปดาห์ · standup · อีเมล · push) · `UserContext.locale` มีตั้งแต่ Phase 0

## การตัดสินใจ

1. **URL เดิม ไม่มี prefix ภาษา** — middleware อ่านคุกกี้ `NOSION_LOCALE` แล้ว rewrite `/today` → `/<locale>/today` ภายใน ·
   หน้าอยู่ใต้ `app/[locale]` + `generateStaticParams` → **static ครบสองภาษา** · ลิงก์และ service worker ไม่ต้องรู้เรื่องภาษา
2. **ไม่เดาจาก `Accept-Language`** — ค่าเริ่มต้นไทยเสมอ (ผลแน่นอนสำหรับเทสต์/Lighthouse) · ปุ่มสลับที่หน้าแรก/login/ตั้งค่า
3. **ภาษาของบัญชี ↔ เครื่อง** — เลือกบนเครื่องนี้ (มีคุกกี้) = บันทึกลงบัญชี · ไม่เคยเลือก = ใช้ของบัญชี · สมัครส่ง `locale` ไปด้วย (อีเมลฉบับแรกถูกภาษา)
4. **โค้ดที่ไม่ใช่ component** (ตัวจัดรูปแบบ · สรุปกฎการเกิดซ้ำ · โมเดล ⌘K · toast) ใช้ตัวแปลกลาง `tr()` ที่ layout ตั้งค่าให้ · ตารางชื่อเป็น getter
5. **ข้อความฝั่งเซิร์ฟเวอร์** อยู่ใน `@nosion/core` (`text(lang, key)`) — `EN: Record<keyof typeof TH>` ภาษาไหนขาด key คอมไพล์ไม่ผ่าน ·
   อีเมลมีชุดของตัวเองใน `@nosion/emails` · ปุ่ม/ป้ายในปฏิทิน (สร้างโดยไม่รู้ภาษา) ส่ง key ให้เว็บแปล
6. **Intl ไทยระบุปฏิทินเสมอ** `th-TH-u-ca-buddhist` / `th-TH-u-ca-gregory` (ค่าเริ่มต้น พ.ศ.) · เงินใช้ `currencyDisplay: 'narrowSymbol'` (฿ ทั้งสองภาษา)
7. **ข้อความ error ของ API ยังเป็นไทย** — เว็บภาษาอังกฤษแสดงข้อความกลางตามชนิดปัญหา (RFC 9457 `type`/status)
8. **ตัวตรวจข้อความ** (`check-messages.mjs` ใน `test:unit`): key ครบทั้งสองภาษา · ICU ถูก · ตัวแปรตรงกัน · ทุก key ที่โค้ดเรียกมีจริง

## ทางเลือกที่ไม่เลือก

| ทางเลือก                                | เหตุผลที่ไม่เลือก                                                                               |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| prefix ใน URL (`/en/today`)             | ต้องแก้ทุก Link/redirect/SW · หน้าเดียวมีสอง URL · ได้ SEO หลายภาษาซึ่งแอปหลังล็อกอินไม่ต้องการ |
| อ่านคุกกี้ตอน render (`cookies()`)      | ทุกหน้ากลายเป็น dynamic → TTFB ของ serverless + cold start ทุกคำขอ                              |
| สลับภาษาฝั่ง client หลังโหลด            | หน้ากระพริบจากไทยเป็นอังกฤษ + hydration mismatch                                                |
| ส่ง `t` ผ่านทุกฟังก์ชันบริสุทธิ์        | เปลี่ยน signature หลายสิบฟังก์ชันและเทสต์ทั้งหมด เพื่อค่าที่ทั้งหน้าใช้ค่าเดียว                 |
| แปลข้อความ error ทุกจุดใน API (~80 จุด) | ต้นทุนสูง ประโยชน์น้อย · ข้อความกลางตาม `type` ถูกต้องเพียงพอสำหรับผู้ใช้                       |
| i18next / react-intl                    | สเปกเลือก next-intl · รองรับ RSC + static rendering ตรงตัว                                      |

## ผลที่ตามมา

**ได้:** build แสดง ● SSG ทุกหน้าทั้งสองภาษา · ไม่มีภาษาไทยปนในหน้าอังกฤษ (ยกเว้นข้อมูลของผู้ใช้) · UI test axe ผ่านทั้งสองภาษา ·
พบบั๊กจริงระหว่างทำ: หน้า server component ที่ลืม `setRequestLocale` ถูก**สร้างชุดอังกฤษเป็นไทย** · key ชนกัน (ข้อความกับกลุ่มชื่อเดียวกัน)

**เสีย:** ตัวแปลกลางเป็น state ระดับ module (ถูกตั้งตอน render — สลับภาษา = โหลดหน้าใหม่) · ข้อความ error ภาษาอังกฤษเจาะจงน้อยกว่าไทย ·
middleware รันทุกคำขอหน้าเว็บ (edge · ไม่กี่ ms) · ข้อมูลตัวอย่างของบัญชีทดลองเป็นไทย
