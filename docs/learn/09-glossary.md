# 09 · อภิธานศัพท์

เรียงตามหมวด · เปิดหาเวลาเจอคำที่ไม่คุ้น

## พื้นฐานเว็บและระบบ

| คำ                          | ความหมาย                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Process**                 | โปรแกรมที่กำลังทำงาน มีหน่วยความจำของตัวเอง ไม่แชร์กับ process อื่น      |
| **Port**                    | หมายเลขช่องทางที่ process จองไว้รับการเชื่อมต่อ (3000 = web, 3001 = api) |
| **HTTP**                    | รูปแบบข้อความมาตรฐานระหว่าง client กับ server                            |
| **Stateless**               | เซิร์ฟเวอร์ไม่จำอะไรจากคำขอก่อนหน้า ทุกคำขอต้องพกหลักฐานมาเอง            |
| **REST**                    | แนวทางออกแบบ API โดยมองทุกอย่างเป็นทรัพยากรที่มี URL                     |
| **Endpoint**                | หนึ่ง method + หนึ่ง path เช่น `POST /auth/login`                        |
| **Payload**                 | เนื้อข้อมูลที่ส่งไปหรือกลับ                                              |
| **Middleware**              | โค้ดที่ทำงานระหว่างทางก่อนถึงปลายทาง                                     |
| **Idempotent**              | ทำซ้ำกี่ครั้งผลลัพธ์เหมือนเดิม                                           |
| **Race condition**          | สองอย่างเกิดพร้อมกันแล้วผลขึ้นกับว่าใครถึงก่อน                           |
| **Graceful shutdown**       | ปิดโปรแกรมโดยทำงานค้างให้จบก่อน                                          |
| **Fail-open / fail-closed** | เมื่อระบบเสริมล่ม เลือก "ปล่อยผ่าน" หรือ "ปฏิเสธทั้งหมด"                 |
| **Defense in depth**        | ป้องกันหลายชั้น ต้องพลาดพร้อมกันทุกชั้นถึงจะรั่ว                         |
| **SSE**                     | Server-Sent Events — เซิร์ฟเวอร์ push ข้อมูลทางเดียวผ่าน HTTP ธรรมดา     |

## เครื่องมือและ monorepo

| คำ                     | ความหมาย                                                          |
| ---------------------- | ----------------------------------------------------------------- |
| **Monorepo**           | หลายโปรเจกต์ใน git repository เดียว                               |
| **Workspace**          | กลุ่มของ package ใน monorepo ที่อ้างถึงกันแบบ local               |
| **pnpm**               | package manager ที่ใช้ store กลาง + symlink แทนการคัดลอก          |
| **Phantom dependency** | ใช้ package ที่ไม่ได้ประกาศใน package.json ได้เพราะ hoisting      |
| **Lockfile**           | บันทึกเวอร์ชันเป๊ะ ๆ ที่ติดตั้ง เพื่อให้ทุกเครื่องได้ของเหมือนกัน |
| **Turborepo**          | ตัวรัน task ที่รู้ลำดับ dependency และ cache ผลลัพธ์              |
| **Task graph**         | แผนผังว่างานไหนต้องเสร็จก่อนงานไหน                                |
| **Transpile**          | แปลงภาษาหนึ่งเป็นอีกภาษา (TS → JS) โดยระดับนามธรรมเท่าเดิม        |
| **CommonJS / ESM**     | ระบบ module สองแบบของ JavaScript (`require` vs `import`)          |
| **Linter**             | โปรแกรมหาโค้ดที่ถูกไวยากรณ์แต่ผิดเจตนา                            |
| **Flat config**        | รูปแบบ config ใหม่ของ ESLint 9 (array ของชุดกฎ)                   |
| **CI / CD**            | ตรวจอัตโนมัติทุกครั้งที่ push / deploy อัตโนมัติเมื่อผ่าน         |
| **Container**          | โปรแกรมที่ห่อมาพร้อม dependency รันบน kernel ของเครื่องแม่        |
| **Multi-stage build**  | Dockerfile ที่แบ่งขั้นตอน เพื่อให้ image สุดท้ายเล็กที่สุด        |

## ฐานข้อมูล

| คำ                          | ความหมาย                                                             |
| --------------------------- | -------------------------------------------------------------------- |
| **PK / FK**                 | Primary key (ระบุแถวไม่ซ้ำ) / Foreign key (ชี้ไปตารางอื่น)           |
| **cuid2**                   | id ที่เดาไม่ได้ + เรียงตามเวลาได้ + สั้นกว่า UUID                    |
| **Index**                   | โครงสร้างที่ทำให้ค้นหาเร็วขึ้น แลกกับการเขียนช้าลง                   |
| **B-tree**                  | index แบบต้นไม้เรียงลำดับ — ชนิดเริ่มต้นของ PostgreSQL               |
| **Composite index**         | index หลายคอลัมน์ — ลำดับคอลัมน์มีผลต่อการใช้งานได้                  |
| **Partial index**           | index เฉพาะแถวที่ตรงเงื่อนไข → เล็กและเร็วกว่ามาก                    |
| **GIN index**               | index สำหรับค่าที่หนึ่งแถวแตกเป็นหลายคีย์ (array, JSONB, trigram)    |
| **pg_trgm**                 | extension ที่ตัดข้อความเป็นชุด 3 ตัวอักษรเพื่อค้นหากลางประโยค        |
| **JSONB**                   | คอลัมน์ JSON ที่เก็บเป็น binary — query และ index ได้                |
| **Soft delete**             | ไม่ลบจริง แต่ใส่ `deletedAt`                                         |
| **Transaction**             | กลุ่มคำสั่งที่สำเร็จทั้งหมดหรือไม่สำเร็จเลย                          |
| **ACID**                    | Atomicity, Consistency, Isolation, Durability                        |
| **ORM**                     | ตัวแปลงระหว่างตารางกับ object ในภาษาโปรแกรม                          |
| **Migration**               | ไฟล์ SQL เรียงตามเวลาที่บันทึกการเปลี่ยนโครงสร้าง                    |
| **N+1 problem**             | ดึงรายการ 1 query แล้ววนดึงรายละเอียดอีก N query                     |
| **Connection pool**         | กลุ่มการเชื่อมต่อที่เปิดค้างไว้หมุนเวียนใช้                          |
| **Zero-downtime migration** | เปลี่ยนโครงสร้างโดยที่โค้ดเก่ากับใหม่รันพร้อมกันได้                  |
| **Outbox pattern**          | เขียน event ลง DB ใน transaction เดียวกับข้อมูล แล้วค่อยส่งออกทีหลัง |

## ความปลอดภัยและ Authentication

| คำ                         | ความหมาย                                                              |
| -------------------------- | --------------------------------------------------------------------- |
| **Authentication (authn)** | ตรวจว่าคุณคือใคร                                                      |
| **Authorization (authz)**  | ตรวจว่าคุณทำสิ่งนี้ได้ไหม                                             |
| **Hash**                   | ฟังก์ชันทางเดียว ย้อนกลับไม่ได้ — ใช้กับรหัสผ่าน                      |
| **Salt**                   | ค่าสุ่มต่างกันทุกผู้ใช้ ผสมก่อน hash เพื่อกัน rainbow table           |
| **Rainbow table**          | ตาราง hash ของรหัสผ่านยอดนิยมที่คำนวณไว้ล่วงหน้า                      |
| **Argon2id**               | อัลกอริทึม hash รหัสผ่านที่เป็น memory-hard (คำแนะนำของ OWASP)        |
| **Memory-hard**            | ต้องใช้ RAM มาก ทำให้เดาแบบขนานด้วย GPU ไม่คุ้ม                       |
| **Timing attack**          | เดาข้อมูลจากความต่างของเวลาตอบกลับ                                    |
| **User enumeration**       | หาว่าอีเมลไหนเป็นสมาชิก จากความต่างของคำตอบหรือเวลา                   |
| **k-anonymity**            | ส่งแค่ส่วนหนึ่งของ hash ไปถาม เพื่อไม่เปิดเผยค่าเต็ม (HIBP)           |
| **JWT**                    | token 3 ส่วน (header.payload.signature) ที่เซ็นแต่ **ไม่ได้เข้ารหัส** |
| **Claims**                 | ข้อมูลใน payload ของ JWT เช่น `sub`, `exp`                            |
| **Access token**           | token อายุสั้นสำหรับเรียก API                                         |
| **Refresh token**          | token อายุยาวสำหรับขอ access token ใบใหม่                             |
| **Opaque token**           | token ที่เป็นค่าสุ่มล้วน ไม่มีข้อมูลในตัว ต้องเทียบกับฐานข้อมูล       |
| **Rotation**               | หมุน refresh token ใหม่ทุกครั้งที่ใช้                                 |
| **Reuse detection**        | ตรวจจับการใช้ token ที่หมุนไปแล้วซ้ำ = สัญญาณว่าถูกขโมย               |
| **Token family**           | กลุ่ม token ที่สืบทอดกันมาจากการ login ครั้งเดียว                     |
| **XSS**                    | ผู้โจมตีทำให้ JS ของเขารันในหน้าเว็บของเรา                            |
| **CSRF**                   | เว็บอื่นสั่งเบราว์เซอร์ยิงคำขอมาที่เว็บเราพร้อม cookie ของผู้ใช้      |
| **httpOnly**               | flag ของ cookie ที่ทำให้ JavaScript อ่านไม่ได้                        |
| **SameSite**               | flag ที่ควบคุมว่า cookie ถูกแนบข้ามเว็บไหม (`Strict` กัน CSRF)        |
| **CORS**                   | กลไกที่เซิร์ฟเวอร์อนุญาตให้ origin อื่นอ่านคำตอบได้                   |
| **Preflight**              | คำขอ `OPTIONS` ที่เบราว์เซอร์ยิงถามก่อนคำขอจริง                       |
| **IDOR**                   | เปลี่ยน id ใน URL แล้วเข้าถึงของคนอื่นได้                             |
| **Rate limiting**          | จำกัดจำนวนคำขอต่อช่วงเวลา                                             |
| **HSTS / CSP**             | header ที่บังคับ HTTPS / จำกัดแหล่งของ script ที่รันได้               |
| **Redaction**              | ลบข้อมูลอ่อนไหวออกก่อนเขียน log                                       |

## สถาปัตยกรรมและ NestJS

| คำ                        | ความหมาย                                                               |
| ------------------------- | ---------------------------------------------------------------------- |
| **Coupling / Cohesion**   | ระดับการผูกกันระหว่างส่วน / ความเกาะกลุ่มภายในส่วน                     |
| **SOLID**                 | หลัก 5 ข้อของการออกแบบเชิงวัตถุ                                        |
| **Open–Closed Principle** | เปิดให้ขยาย ปิดต่อการแก้ไขของเดิม                                      |
| **Dependency Injection**  | ไม่สร้างของที่ต้องใช้เอง แต่รับเข้ามาทาง constructor                   |
| **IoC Container**         | ตัวประกอบ object ให้อัตโนมัติตามที่แต่ละคลาสประกาศไว้                  |
| **Provider**              | สิ่งที่ container สร้างและแจกจ่ายได้                                   |
| **Token (DI)**            | กุญแจที่ใช้อ้างถึง provider (คลาส หรือ Symbol)                         |
| **Singleton**             | สร้างครั้งเดียว ใช้ร่วมกันทั้งแอป                                      |
| **Decorator**             | ฟังก์ชันที่ถูกเรียกตอนประกาศคลาสเพื่อแปะข้อมูลเพิ่ม                    |
| **Metadata**              | ข้อมูลกำกับที่ถูกฝังไว้และอ่านได้ตอนรัน (`reflect-metadata`)           |
| **DiscoveryService**      | เครื่องมือของ NestJS ที่เดินดู provider ทุกตัวตอนรัน                   |
| **Registry pattern**      | ทะเบียนกลางที่เก็บรายการของปลั๊กอินทั้งหมด                             |
| **Guard**                 | ตัวตัดสินว่าคำขอนี้ผ่านเข้าไปได้ไหม                                    |
| **Pipe**                  | ตัวแปลง/ตรวจข้อมูลก่อนเข้า handler                                     |
| **Exception filter**      | ตัวดัก error แล้วแปลงเป็น response                                     |
| **Lifecycle hook**        | ฟังก์ชันที่ framework เรียกในจังหวะที่กำหนด (`onApplicationBootstrap`) |
| **Event bus**             | ช่องทางประกาศเหตุการณ์ให้ผู้สนใจฟัง โดยสองฝ่ายไม่รู้จักกัน             |

## API และการตรวจข้อมูล

| คำ                         | ความหมาย                                                 |
| -------------------------- | -------------------------------------------------------- |
| **RFC 9457**               | มาตรฐานรูปแบบ error ของ HTTP (Problem Details)           |
| **DTO**                    | Data Transfer Object — รูปร่างข้อมูลที่รับ/ส่ง           |
| **Zod**                    | ไลบรารีประกาศ schema ที่ให้ทั้งการตรวจตอนรันและ type     |
| **Parse, don't validate**  | ตรวจแล้วคืนข้อมูลชนิดใหม่ที่การันตีว่าถูก                |
| **Boundary**               | จุดที่ข้อมูลจากภายนอกเข้าสู่ระบบ — ที่ที่ต้องตรวจ        |
| **Cursor pagination**      | แบ่งหน้าโดยจำจุดที่อ่านค้างไว้ แทนการนับ offset          |
| **Optimistic concurrency** | ไม่ล็อก แต่ตรวจ version ตอนบันทึก                        |
| **Lost update**            | การแก้ของคนหนึ่งถูกเขียนทับโดยไม่มีใครรู้                |
| **Trace ID**               | รหัสประจำคำขอ ใช้ร้อยเรียง log ทั้งสาย                   |
| **AsyncLocalStorage**      | กลไกของ Node ที่พาค่าประจำคำขอไปกับทุกฟังก์ชันในสายนั้น  |
| **Liveness / Readiness**   | ยังอยู่ไหม (ควรรีสตาร์ต) / พร้อมรับงานไหม (ควรถอดจาก LB) |
| **OpenAPI / Swagger**      | สเปกอธิบาย API / UI ที่ generate จากสเปกนั้น             |

## Frontend

| คำ                            | ความหมาย                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------- |
| **Component**                 | ฟังก์ชันที่คืน UI                                                            |
| **Props / State**             | ข้อมูลที่รับจากแม่ / ข้อมูลที่เปลี่ยนแล้วต้องวาดใหม่                         |
| **Re-render**                 | React เรียก component ใหม่เมื่อ state เปลี่ยน                                |
| **Virtual DOM**               | โครงสร้างจำลองที่ React ใช้เทียบก่อนแก้ DOM จริง                             |
| **Hook**                      | ฟังก์ชัน `use*` ที่ต่อยอดความสามารถให้ component                             |
| **SPA / SSR / RSC**           | วาดในเบราว์เซอร์ / วาดที่เซิร์ฟเวอร์ / component ที่รันบนเซิร์ฟเวอร์เท่านั้น |
| **Hydration**                 | การที่ JS เข้าไป "ต่อสาย" ให้ HTML ที่เซิร์ฟเวอร์ส่งมา                       |
| **`'use client'`**            | ประกาศว่าไฟล์นี้เป็น Client Component                                        |
| **Route group**               | โฟลเดอร์ `(ชื่อ)` ที่ใช้จัดกลุ่มโดยไม่กระทบ URL                              |
| **Server state**              | ข้อมูลที่เซิร์ฟเวอร์เป็นเจ้าของ เราถือแค่สำเนาที่อาจล้าสมัย                  |
| **Client state**              | สถานะของหน้าจอนี้เท่านั้น เช่น ธีม, sidebar                                  |
| **Query key**                 | กุญแจที่ TanStack Query ใช้แยกชุดข้อมูลในแคช                                 |
| **staleTime**                 | ระยะเวลาที่ถือว่าข้อมูลยังสด ไม่ต้องดึงใหม่                                  |
| **Optimistic update**         | อัปเดต UI ทันทีก่อนเซิร์ฟเวอร์ตอบ แล้วย้อนกลับถ้าพลาด                        |
| **Single-flight**             | หลายคนขอพร้อมกัน แต่ยิงจริงครั้งเดียวแล้วแชร์ผล                              |
| **Controlled / Uncontrolled** | React ถือค่าในฟอร์ม / ปล่อยให้ DOM ถือ                                       |
| **Design token**              | ตัวแปรกลางของสี/ระยะ/มุมโค้ง ที่ทุก component อ้างถึง                        |
| **Layout shift (CLS)**        | เนื้อหากระโดดตอนโหลด — ตัวชี้วัดหนึ่งของ Core Web Vitals                     |
| **a11y**                      | accessibility (ตัวอักษร 11 ตัวระหว่าง a กับ y)                               |
| **ARIA**                      | ชุด attribute ที่บอกความหมายของ UI ให้ screen reader                         |

## การทดสอบ

| คำ                           | ความหมาย                                                      |
| ---------------------------- | ------------------------------------------------------------- |
| **Unit / Integration / E2E** | ทดสอบชิ้นเดียว / หลายชิ้นต่อกันจริง / ทั้งระบบผ่านเบราว์เซอร์ |
| **Stub / Mock / Fake / Spy** | ของปลอม 4 แบบ (ดูไฟล์ 08)                                     |
| **AAA**                      | Arrange, Act, Assert — โครงของเทสต์ที่ดี                      |
| **Coverage**                 | สัดส่วนโค้ดที่ถูกรันระหว่างเทสต์ (ไม่ใช่ตัววัดคุณภาพโดยตรง)   |
| **Flaky test**               | เทสต์ที่ผ่านบ้างไม่ผ่านบ้างโดยโค้ดไม่เปลี่ยน                  |
| **Testing pyramid**          | สัดส่วนที่ควรเป็น: unit เยอะสุด E2E น้อยสุด                   |
| **DLQ**                      | Dead Letter Queue — ที่พักของงานที่ retry จนครบแล้วยังล้มเหลว |
