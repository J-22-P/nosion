## 1. ทำไม rule-based และทำไมต้องตัวเดียว

ก่อน Phase 5 มี parser สามชุด: งาน (regex "พรุ่งนี้" = ตอนนี้ + 24 ชม. **ตามเวลา server**), รายจ่าย (regex เงิน + "ทุกวันที่ N"),
และหน้าเว็บ (regex `!#+` สำหรับ chip) — "พรุ่งนี้" ของสามที่นี้ไม่เท่ากัน

ตัวเลือกที่ดูทันสมัยคือส่งให้ LLM แต่ ⌘K ขอ preview ทุก 250ms ระหว่างพิมพ์: หลายร้อย ms และมีค่าใช้จ่ายทุกครั้ง, ผลไม่คงที่ (เทสต์แบบตารางไม่ได้)
และใช้ในเบราว์เซอร์ตอน offline ไม่ได้ · rule-based ตอบใน < 1 ms ให้ผลเดิมทุกครั้ง

📁 `packages/core/src/nl.ts` → `parseNaturalText(input, { now, timeZone, weekStartsOn })` · subpath `@nosion/core/nl` ไม่ import rrule และไม่แตะ Node
→ ใช้ได้ทั้ง API และเบราว์เซอร์ (กฎ lint ของ web อนุญาตเฉพาะ subpath)

🎤 _"ทำไมไม่ใช้ chrono-node"_ → ไม่รู้จัก "บ่าย 2", "2 ทุ่ม", "ตี 5", ปี พ.ศ. และไม่มีการเกิดซ้ำ/เงิน/แท็ก — ส่วนที่ยากที่สุดยังต้องเขียนเอง

## 2. Mask-and-scan

ภาษาไทยไม่มีช่องว่างระหว่างคำ จึง tokenize ด้วยช่องว่างไม่ได้ · parser จึง "สแกนหาสิ่งที่รู้จัก" แทนการตัดคำ:

```
input : "ค่าเน็ต 799 ทุกวันที่ 5 #บ้าน"
1. การเกิดซ้ำ "ทุกวันที่ 5"     → masked: "ค่าเน็ต 799            #บ้าน"
2. วันที่ / เวลา                 → (ไม่เจอ)
3. สัญลักษณ์ "#บ้าน"             → masked: "ค่าเน็ต 799                  "
4. ตัวเลข "799"                  → amount
title = ส่วนที่ไม่ถูกหยิบ = "ค่าเน็ต"
```

- **ลำดับคือกติกา** — การเกิดซ้ำต้องมาก่อนวันที่ ("ทุกวันที่ 5" ไม่ใช่ "วันที่ 5") และวันที่/เวลาต้องมาก่อนเงิน ("5 โมง" ไม่ใช่ 5 บาท)
- **ทับด้วยช่องว่างยาวเท่าเดิม** → `start/end` ของทุก token ชี้ข้อความเดิมได้ตรง ใช้ highlight ใน ⌘K และแก้ chip
- เลขไทย ๐–๙ ถูกแทนด้วยเลขอารบิกก่อนสแกน — ตัวละหนึ่งตัวเท่าเดิม ตำแหน่งจึงไม่เลื่อน

⚠️ กับดัก: ตำแหน่งเป็น **UTF-16 index** แบบ `String.slice` · ถ้าตัดข้อความด้วย `[...input]` (ทีละ code point) emoji หนึ่งตัวจะทำให้ตำแหน่งเลื่อนไป 1
— `stripTokens` ใช้ `slice` ตลอด

### 2.1 ขอบคำ: ไทยไม่ใช้ อังกฤษต้องใช้

- คำไทยจับได้แม้ติดกัน: `ส่งรายงานพรุ่งนี้` → "พรุ่งนี้"
- อังกฤษและตัวเลขต้องอยู่ต้นคำ (lookbehind `(?<=^|[\s,(])`) — ไม่งั้น "ais5g" มีเงิน 5 บาท, "C#" มีแท็ก, "1+1" มีโปรเจกต์
- ชื่อวันไทยเปล่า ๆ ต้องอยู่ต้นคำหรือมี "วัน" นำ — "พระจันทร์" ไม่ใช่วันจันทร์

### 2.2 เวลาแบบไทย

| พิมพ์       | ได้   | กติกา                                                    |
| ----------- | ----- | -------------------------------------------------------- |
| ตี 5        | 05:00 | ตี 1–5                                                   |
| 8 โมงเช้า   | 08:00 |                                                          |
| 5 โมง       | 17:00 | ไม่ระบุช่วง: 1–6 = บ่าย/เย็น, 7–11 = เช้า (ตัวอย่างสเปก) |
| บ่าย 2      | 14:00 | บ่ายโมง = 13:00                                          |
| 2 ทุ่ม      | 20:00 | 18 + N                                                   |
| 10 โมงครึ่ง | 10:30 | "ครึ่ง" = +30 นาที                                       |

## 3. "พรุ่งนี้" ของใคร

📁 `nl.ts` คำนวณวันเป็นสตริง `'YYYY-MM-DD'` จาก `formatInTimeZone(now, timeZone)` แล้วค่อยแปลงเป็น UTC ตอนท้ายด้วย `zonedTimeToUtc`
→ 23:30 ที่นิวยอร์ก (= 03:30 UTC วันถัดไป) "tomorrow" ยังเป็นวันถัดไปของนิวยอร์ก (เทสต์ "พรุ่งนี้เป็นของผู้ใช้")

กติกาที่ต้องตัดสินใจเอง (บันทึกใน phase ขั้น 1):

- **วันในสัปดาห์นับวันนี้ด้วย** ("ส่งงานศุกร์" ตอนวันศุกร์ = วันนี้) · "ศุกร์หน้า / next friday" = +7 ถ้าวันนั้นยังอยู่ในสัปดาห์นี้ (ขึ้นกับ `weekStartsOn`)
- **"อาทิตย์" ไม่มี "วัน" นำ = สัปดาห์** — "ทุกอาทิตย์" = ทุกสัปดาห์, "อาทิตย์หน้า" = สัปดาห์หน้า · "วันอาทิตย์หน้า" = วันอาทิตย์
- **เวลาที่ผ่านไปแล้วไม่ระบุวัน = รอบถัดไป** ("standup 9am" ตอน 10 โมง = พรุ่งนี้) — การเตือนของเวลาที่ผ่านมาแล้วไม่มีประโยชน์
- ไม่ระบุปีแล้ววันผ่านไปแล้ว = ปีหน้า · ระบุปีเอง = ใช้ตามนั้น (บันทึกย้อนหลังได้) · 31/2 = ไม่ใช่วันที่
- รอบแรกของ `ทุกวันที่ 31` ในเดือนที่มี 30 วัน = วันที่ 30 (clamp — ADR-010)

🎤 _"ทดสอบ parser อย่างไรให้มั่นใจ"_ → table-driven 80 เคส **เทียบทุกฟิลด์** (ฟิลด์ที่ไม่ระบุต้องว่าง) — จับได้ทั้ง "ไม่เข้าใจ" และ "กินคำเกิน"
ซึ่งอย่างหลังคือบั๊กที่เจอบ่อยกว่า (เช่น "iphone 15 pro 35900" ได้เงิน 15)

## 4. Parser แยกชิ้น — โมดูลตีความ

```ts
// packages/core/src/module.interface.ts
parseNaturalLanguage(text: NlResult, ctx: UserContext): ParsedEntry | null;
```

📁 `apps/api/src/core/parser/parser.service.ts` — parse ครั้งเดียว ส่ง `NlResult` ตัวเดียวกันให้ทุกโมดูลที่ผู้ใช้เปิด เรียงตาม `confidence`

- รายจ่าย (`expense-text.ts → interpretExpense`): ต้องมีเงิน · เดาหมวดจากคำที่ยาวที่สุด · รายเดือน/รายปี = บิล + เตือนล่วงหน้า 1 วัน 09:00 ·
  ทั่วไป = `status: done` (เกิดขึ้นแล้ว)
- งาน (`task.trackable.ts`): รับทุกข้อความ (ทางเลือกสุดท้าย) แต่มีเงินไม่มีวัน → ความมั่นใจ ≤ 0.25 และ **ชื่อเก็บตัวเลขไว้** ("งาน 'กาแฟ 65'")
  · ระบุเวลา = เตือนตอนนั้น · ระยะเวลา → `estimateMinutes`

📁 `apps/api/src/parse/parse.service.ts` → `commit` **parse ข้อความใหม่ที่ server เสมอ** ไม่รับ payload จาก client ·
มี `rrule` = `RecurrenceService.create` (materialize + การเตือนของทุกรอบ) แล้วคืนรอบแรก · แท็ก/โปรเจกต์ผูกของเดิมแบบไม่สนตัวพิมพ์ ไม่มีก็สร้าง

⚠️ กับดักที่เจอจริง (ขั้น 8): "กาแฟ 65" จาก ⌘K เคยบันทึกเป็น `pending` ขณะที่บันทึกด่วนหน้า Expenses เป็น `done` — สองทางเข้าของข้อมูลชนิดเดียวกัน
ต้องตัดสินที่เดียว → `ParsedEntry.status` ให้โมดูลกำหนด

## 5. ปฏิทินรวม: query เดียว และมองไปข้างหน้าโดยไม่เขียน DB

📁 `apps/api/src/calendar/calendar.service.ts` — entry ทุกโมดูลในช่วงพร้อมการเตือน (`include`) **ใน query เดียว** แล้ว
📁 `calendar-events.ts → buildCalendar` ให้แต่ละโมดูล `toCalendarEvent` (ขึ้นไหม หน้าตาอย่างไร) และ `calendarActions` (มีปุ่มอะไร)

**projected events** — กฎการเกิดซ้ำสร้างรายการล่วงหน้าแค่ 90 วัน (บท 16) เลื่อนปฏิทินไป 4 เดือนแล้วบิลรายเดือนจะหายไปเฉย ๆ ·
📁 `RecurrenceService.projectedEntries` คำนวณรอบที่เลย `materializedUntil` จากกฎ เป็น entry ชั่วคราว (`projected: true`, `entryId: null`, ไม่มีปุ่ม)

🎤 _"ทำไมไม่ materialize ตามช่วงที่ผู้ใช้เปิดดูไปเลย"_ → การอ่านไม่ควรเขียน DB (GET ต้อง idempotent และ cache ได้) · ผู้ใช้เลื่อนไปไกลแค่ดูแล้วจากไปก็จะทิ้ง
แถวไว้เต็ม DB · cron เติมให้เองเมื่อใกล้ถึง

- `countsByModule` นับก่อนกรอง `?module=` — chip ที่ไม่ได้เลือกยังบอกจำนวนได้
- ช่วงวันที่รับเป็น "วันบนปฏิทินของผู้ใช้" และ `to` รวมทั้งวัน → ขอบบน = ต้นวันถัดไปตามโซน · จำกัด 93 วันต่อคำขอ

## 6. iCal (RFC 5545)

📁 `apps/api/src/calendar/ical.ts` — สิ่งที่ทำให้ Google/Apple อ่านไม่ออกถ้าพลาด:

- บรรทัดจบด้วย **CRLF** และยาวไม่เกิน **75 octet** — ไทยหนึ่งตัว = 3 byte ใน UTF-8 · `foldLine` นับ byte ด้วย `TextEncoder` ทีละตัวอักษร
  ไม่ตัดกลางตัว แล้วต่อบรรทัดด้วย CRLF + ช่องว่าง (client ลบสองตัวนี้แล้วต่อกลับ)
- escape `\ ; ,` และขึ้นบรรทัดใหม่เป็น `\n`
- ทั้งวัน = `DTSTART;VALUE=DATE:20261031` + `DTEND` เป็น **วันถัดไป** (exclusive) · มีเวลา = UTC `…Z`
- **UID คงที่** — รอบของกฎใช้ `ruleId + เวลา slot` จึงเป็น event เดียวกันทั้งตอน projected และหลังถูกสร้างจริง (ไม่ซ้ำในแอปปฏิทิน)

ลิงก์ `/calendar/:token.ics` ไม่ต้องล็อกอิน — **token คือ credential** · rotate แล้วลิงก์เดิม 404 ทันที ·
เก็บแบบอ่านได้ (ไม่ hash) เพราะสเปกให้ dialog คัดลอกลิงก์ได้ทุกเมื่อ — ถ้า hash ทุกครั้งที่อยากดูลิงก์ต้อง rotate ซึ่งตัด subscription เดิม

## 7. ลากเปลี่ยนวัน: optimistic, rollback, version และ DST

📁 `apps/web/src/features/calendar/use-calendar.ts → useMoveEvent`

```
onMutate  → cancelQueries + เก็บแคชเดิม + ย้ายในแคชทันที
mutationFn→ PATCH /entries/:id { occurredAt, isAllDay, version }
onError   → คืนแคชเดิม (409 = มีคนแก้ก่อน → บอกให้ลองใหม่)
onSettled → invalidate ['entries'] (ทุกหน้าที่แสดงรายการนี้)
```

- `version` มากับ `/calendar` เพื่อสิ่งนี้ — แท็บสองแท็บลากรายการเดียวกัน คนช้ากว่าได้ 409 ไม่เขียนทับ
- 📁 `grid.ts → moveTarget` **คงเวลาหน้าปัด**: 09:00 ที่นิวยอร์กก่อน DST สิ้นสุด (13:00 UTC) ย้ายไปหลัง DST = 14:00 UTC ยังเป็น 09:00 ·
  ถ้าบวก 24 ชม. × จำนวนวันตรง ๆ จะกลายเป็น 08:00
- รายการจากกฎย้าย **เฉพาะรอบนั้น** — API เพิ่มวันเดิมเข้า exceptions และเลื่อน `fireAt` ของการเตือนตาม (บท 16–17)
- HTML5 drag-and-drop ใช้เมาส์อย่างเดียว (WCAG 2.1.1) และใช้นิ้วบนมือถือไม่ได้ → ช่อง "ย้ายไปวัน" ใน day panel แก้ทั้งสองกรณี

⚠️ กับดัก: ของที่ลากได้ซ้อนอยู่ใน `<button>` ลากไม่ขึ้นในบางเบราว์เซอร์ → ช่องวันเป็น `div` + ปุ่มเลือกวันปูเต็มช่องด้านล่าง

⚠️ กับดักของเทสต์: mock API ไม่มี state — หลังบันทึกสำเร็จ `invalidate` ดึงข้อมูลเดิมกลับมา รายการ "เด้งกลับ" ·
ตรวจ optimistic โดย **ค้างคำตอบของ route ไว้** จนตรวจเสร็จ

## 8. ⌘K

📁 `apps/web/src/features/command-palette/`

- **3 โหมดในกล่องเดียว**: ว่าง = ไปหน้า · `>` = คำสั่ง · อื่น ๆ = "สร้าง…" + "หรือสร้างเป็น…" + ผลค้นหา พร้อมกัน
- highlight ส่วนที่เข้าใจ **ทันที** จาก parser ฝั่ง client · `/parse` + `/entries?q=` หลัง debounce 250ms
- preview ยังไม่ตามทันข้อความ (กด ↵ ภายใน 250ms) → ไม่ส่ง `module` ให้ server เลือกเอง · `clientId` ต่อข้อความ กด ↵ รัวไม่สร้างซ้ำ
- ↵ ระหว่างเลือกคำใน IME (`isComposing`) ไม่ใช่การยืนยัน

**ARIA combobox** — โฟกัสอยู่ที่ `<input role="combobox">` ตลอด รายการเป็น `role="listbox"` / `option` และบอกตัวที่เลือกด้วย
`aria-activedescendant` (ไม่ย้ายโฟกัสจริง) → screen reader อ่านรายการที่เลื่อนไปโดยผู้ใช้พิมพ์ต่อได้

⚠️ **race ของ `<dialog>`** (ขั้น 9): `dialog.close()` ส่ง event `close` แบบ async · ถ้ากด ⌘K เปิดใหม่ก่อน event ของการปิดครั้งก่อนมาถึง
handler `onClose → setOpen(false)` จะปิด palette ที่เพิ่งเปิด · แก้: `onClose` ตั้งสถานะปิดเฉพาะเมื่อ `dialog.open === false` ·
เจอจากเทสต์ที่ล้มเฉพาะตอนเครื่องโหลดหนัก — **เทสต์ที่ flaky มักกำลังบอก race จริง**

## 9. ข้อความคือแหล่งความจริงเดียวของ chip

📁 `apps/web/src/features/capture/nl-chips.ts` — chip มาจาก token ของ parser · แก้ chip = **เขียนข้อความส่วนนั้นใหม่**
ด้วยรูปที่ parser อ่านกลับได้ชนิดเดิมแน่นอน (วันที่ → `9/10/2026`, เวลา → `09:30`, priority → `!low`) · date picker ข้างช่องก็เขียนลงข้อความ

ทำไม: ถ้า chip มี state ของตัวเอง (วันที่ที่เลือกแยกจากข้อความ) จะมีสองความจริงที่ต้อง merge ตอนบันทึก — และ server ซึ่ง parse ข้อความ
จะเห็นคนละอย่างกับที่ผู้ใช้เห็น · เทสต์ **round-trip**: แก้ chip → parse ข้อความใหม่ → ได้ค่าใหม่ชนิดเดิม

ข้อยกเว้นเดียว: หมวดของรายจ่าย (server เดา ไม่ได้มาจากข้อความ) → `payloadPatch` ตรวจด้วย payloadSchema ของโมดูลเหมือน `POST /entries`

## 10. ปุ่มลัด

📁 `apps/web/src/lib/shortcuts/`

- `createKeyReader()` — pure, รับเวลาเป็นพารามิเตอร์ · `g` จำค้างไว้ 1 วินาที: `g c` = ปฏิทิน · เกินเวลาหรือปุ่มอื่น = อ่านปุ่มนั้นตามปกติ
  (`g` แล้วรอนาน → `k` = รายการก่อนหน้า ไม่ใช่ไปหน้างาน)
- **หาเป้าหมายจาก DOM ไม่ hard-code หน้า**: `n` → `[data-shortcut="new"]` ตัวแรกที่มองเห็น (ไม่มี = palette) · `j/k` → `[data-shortcut-item]`
  — หน้าใหม่ได้ปุ่มลัดแค่ติด attribute
- ปุ่มระดับรายการ (`e t x 1–4`) อยู่ที่การ์ด และทำงานเมื่อ **การ์ดเอง** ถูกโฟกัส — Enter/Space ของปุ่มข้างในยังทำงานปกติ
- ไม่แย่งปุ่มตอนพิมพ์ (⌘Z ในช่องพิมพ์ = undo ข้อความ) และตอนมี dialog เปิด — ยกเว้น ⌘K

**⌘Z ต้องรู้ version** — ย้อน "ติ๊กเสร็จ" = PATCH `status: pending` พร้อม version **หลัง**ติ๊ก ซึ่งรู้เมื่อ server ตอบ ·
ผู้กระทำลงทะเบียนวิธีย้อนใน `onSuccess` (📁 `undo-store.ts`) · ลบ → `POST /entries/:id/restore` (soft delete ทำให้ย้อนได้)

## ข้อเสียที่ยอมรับ

- parser ไม่เข้าใจสิ่งที่ไม่มีกฎ ("อีกสามวัน", "สองทุ่ม" แบบตัวอักษร) และตัดสินความกำกวมด้วยกติกาตายตัว (ADR-012)
- รอบ projected กดอะไรไม่ได้จนกว่า cron จะสร้างจริง · การเตือนของรายการนอกช่วงไม่ติดจุดบน cell
- token iCal เก็บแบบอ่านได้ · Google ดึง feed ตามรอบของตัวเอง (หลายชั่วโมง) ไม่สน `REFRESH-INTERVAL`
- ลากได้เฉพาะเมาส์ (มีช่องเลือกวันแทน) · ลากเปลี่ยนเวลาไม่ได้
- ⌘Z ย้อนการทำหลายรายการพร้อมกันไม่ได้ และหายเมื่อรีเฟรช
- smoke ของ DoD (API จริง) ยังไม่อยู่ใน CI

## แบบฝึกหัดท้ายบท

1. สลับลำดับใน `parseNaturalText` ให้ `scanNumbers` มาก่อน `scanRecurrence` แล้วรันตารางเทสต์ — เคสไหนพังบ้าง และพังแบบ "ไม่เข้าใจ" หรือ "กินคำเกิน"
2. เพิ่ม matcher "อีก N วัน / in N days" พร้อม 4 เคสในตาราง โดยไม่ทำให้เคสเดิมเปลี่ยน
3. ใส่ emoji ไว้หน้า "ค่าเน็ต 799" แล้วเปลี่ยน `stripTokens` เป็น `[...input].map(...)` — title ผิดอย่างไร ทำไม
4. ตั้ง `weekStartsOn = 0` แล้วคำนวณ "ศุกร์หน้า" และ "สัปดาห์หน้า" ของวันเสาร์ — ตรงกับที่คนไทยคาดไหม
5. เขียน `toCalendarEvent` ของโมดูลสมมติ "habit" ที่ขึ้นปฏิทินเฉพาะวันที่ยังไม่ทำ แล้วตรวจว่า `GET /calendar` แสดงโดยไม่แก้ `calendar.service.ts`
6. สร้าง `.ics` ที่มีชื่อรายการไทย 40 ตัว แล้วนับ byte ของแต่ละบรรทัดที่พับ — ถ้าพับตามจำนวนตัวอักษร (75 ตัว) บรรทัดจะยาวกี่ byte
7. เปลี่ยน `moveTarget` ให้บวก `86_400_000 × จำนวนวัน` แล้วรันเทสต์ New York — ได้เวลาเท่าไร
8. ลบเงื่อนไข `if (!ref.current?.open)` ใน `onClose` ของ palette แล้วเขียนเทสต์ที่ล้มทุกครั้ง (ไม่ต้องพึ่งเครื่องช้า) — ต้องกดอะไรในจังหวะไหน
9. ให้ chip วันที่เก็บค่าใน `useState` แยกจากข้อความ แล้วพิมพ์ "พรุ่งนี้" ทับ — ส่วนไหนของระบบเห็นวันไหน
10. ทำให้ ⌘Z ย้อน bulk complete ได้ — ต้องรู้อะไรเพิ่มจาก `POST /entries/bulk`
